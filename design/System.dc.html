Foundations

Everything an implementation agent needs to build the pages without re-deciding anything. Values are literal; contrast figures are measured against the cream ground #F7F7F8.

Colour

Lifted from Dispatch Energy's own site: white and near-white grounds, near-black text, their greys (#E2E2E2, #C2C2C2, #8F8F8F, #58595B) for rules and secondary text, and one accent — their green #006400 — for eyebrow labels, links, the success state and every data mark. One exception, and only one: the PVWatts production bars — the estimate the app exists to produce — are solar orange. Everything else on every screen is green: labels, links, status, map markers, selection, progress, and the irradiance charts in a lighter step of the same green. Solar orange never marks a status, and no status colour ever carries a data series.

Charts
  • Form — twelve ordered months of a single measure is a column chart. One measure per chart; never two y-axes.
  • Colour — one hue. Every chart is a single series: PVWatts production in solar orange #C96A1C, irradiance in the lighter green #3E8E4F. Height carries the magnitude, so colour never varies within a series.
  • Labels — the peak and trough are labelled directly; the rest are read from the axis or on hover. No number on every column.
  • Grid — three horizontal rules at #ECECEC, a stronger baseline, no vertical grid, no chart border, no drop shadow.
  • Legend — none for a single series; the heading names it and states the unit.
  • Small multiples — GHI, DNI and latitude tilt share one 0–8.6 scale so their shapes compare honestly; the shared scale is stated in words beneath them.
  • Hover — a dark tooltip with month, value and unit; the column darkens to #004D00. Keyboard arrows move the same focus, and the tooltip text is announced.
  • Table — every chart is backed by the same numbers in a months-as-columns table on the same page. The chart is never the only way to read a value.
  • Never — no zero substituted for a missing month, no interpolation across a failed stage, no truncated y-axis.
Interaction, keyboard and motion
  • Focus — a 2px #101010 outline with a 2px offset on every interactive element, including map markers. Never removed, never colour-only.
  • Tab order — skip link, app bar, catalog rows in list order, then the map as one stop; arrow keys then move between markers.
  • Rows — the whole catalog row is one link, minimum 44px tall on touch. Selection is marked by a 4px solar left rule plus a tinted background, so it does not rely on colour alone.
  • Layered detail in the rail — a resting row shows name, address, coordinates and annual production. Hover or focus reveals one extra line: GHI, DNI and latitude-tilt annual averages as three micro-bars in irradiance teal. The selected row keeps that line open, and the map callout carries the same three figures. Nothing else is added on hover.
  • Map ↔ list — hovering or focusing either side highlights the other. Selecting a marker scrolls its row into view and vice versa.
  • Destructive actions — anything that clears stored results (address change, geocode refresh) states what will be lost before it runs, and its confirming button carries the failed colour.
  • In flight — the control becomes its own progress indicator, is disabled for the duration, and repeat submissions are ignored. Surrounding data stays on screen until it is replaced.
  • Announcements — stage outcome changes are written to a polite live region: "Solar resource retried — succeeded".
  • Reduced motion — under prefers-reduced-motion, spinners become a static label, map pans jump, and nothing else animates. No motion is load-bearing.
Map styling
  • Standard OpenStreetMap raster tiles, desaturated slightly so solar markers stay the brightest thing on screen.
  • Marker: 11px solar disc, 2px panel-coloured ring, plus a soft halo. Selected: 16px, deep solar, 2.5px ring.
  • Fully interactive: drag to pan, scroll or the +/− control to zoom, and a "Fit to sites" control to return to all markers. Keyboard: arrows pan, +/− zoom.
  • Initial view fits the resolved markers, framing the contiguous United States when there are none.
  • Opening or closing the list re-fits the bounds with the rail's width as left padding, so a west-coast marker is never left behind the panel. Collapsing the rail hands the full width to the map.
  • A permanent legend states that only resolved sites appear, and counts the ones that do not.
  • Tile attribution and Nominatim geocoding attribution are separate lines — the geocoding credit also appears on the detail page, which has no map.
  • Nothing on the map triggers a lookup: no search box, no autocomplete, no geocode on pan.
Spacing, rules and panels
  • Spacing scale: 2, 4, 6, 8, 10, 12, 14, 16, 18, 24. Panel padding 14–18px; section gap 14px.
  • Separation is a 1px rule, not a shadow. Shadows appear only on the map callout, which floats above tiles.
  • Panels are 1px #E2E2E2 on #FFFFFF, 3px radius. No nested cards, no card inside a card.
  • A stage that failed carries a 3px left rule in its status colour — the one place a whole panel is tinted.
  • Layout breakpoints: split view ≥1100px, stacked below, phone treatment ≤640px.
  • Catalog rail is fixed at 400px; the map takes the rest and never falls below 560px before stacking.
